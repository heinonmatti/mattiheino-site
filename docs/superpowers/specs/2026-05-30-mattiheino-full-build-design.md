## 1. Context

The current mattiheino.com runs on WordPress.com. It is slow, ornament-heavy, and limits typographic and performance work. The replacement is an Astro + Cloudflare Pages site whose visual identity ("Letterhead") and scaffold are already built and running locally (`localhost:4321`).

Two content streams need to merge into the new site:

- **mattiheino.com (104 published posts + 17 drafts + 9 pages)** – preserved from the WordPress.com export taken on 2026-05-20. Already visible to readers on the live site; remains visible after cutover.
- **motivationselfmanagement.com (12 recoverable posts via Wayback)** – Matti's recovered domain, formerly Bluehost / WordPress.org. Content sits in a related-but-popular register and absorbs into the new site's `applied-musings/` collection as **drafts**, never auto-publishing.

Vetting drives two pipelines: legacy mattiheino posts go through a *social repost* trigger; MSM posts go through a *first-publication* trigger that flips `draft: false`. Both pipelines converge in the same cross-poster Worker (Phase 6, out of scope here).

## 2. Goals and non-goals

**Goals.**
- Ship a fully bilingual mattiheino.com on Astro + Cloudflare Pages with reader-visible content equivalent to the WordPress.com archive.
- Preserve every existing URL by 301 where the new slug differs, and every existing RSS subscriber by `<guid>` so they do not re-receive the archive as "new".
- Recover 12 motivationselfmanagement.com posts from Wayback into the new site as drafts (never auto-published).
- Redirect every motivationselfmanagement.com URL to the new site (fallback-only initially, per-URL appended as posts go live).
- Surface a `/vetting-queue/` internal page that splits the two pipelines cleanly so Matti can work through each without confusion.

**Non-goals.**
- Build a cross-poster Worker. The schema is shaped for it (`social_status`, `social_copy`, etc.) but the Worker itself is Phase 6.
- Migrate the WP.com email subscribers to Listmonk. Separate pre-cutover task.
- Add a dark mode. Light cream is the brand.
- Build any kind of CMS UI. Editing happens in VS Code / Positron against the typed content schema.

## 3. Architecture (locked, summary only)

- **Stack.** Astro 6.3 with content collections; Cloudflare Pages for hosting; GitHub repo auto-deploys on push to `main`.
- **Newsletter.** Reuses the existing Listmonk + `mattiheino-newsletter` Worker at `news.mattiheino.com`. Site links through; no inline form in v1.
- **Brand.** Per `BRAND.md` (Letterhead direction C). Sky band + Newsreader + Inter + cream/red pair + 64ch measure + 17 px body.
- **Performance budget.** Near-zero client JS (filter row + row-expand only). Cloudflare Web Analytics (cookieless). Self-hosted Newsreader + Inter via `@fontsource-variable`.
- **Search.** Pagefind, generated by `postbuild`. Only loaded on `/search/`.

## 4. Schema additions

The existing Zod schema (`src/content.config.ts`) gains **two new optional fields** in `baseSchema`:

```ts
wp_guid: z.string().optional(),    // original WordPress <guid> for RSS continuity
msm_slug: z.string().optional(),   // original motivationselfmanagement.com slug for lazy redirect generation
```

- `wp_guid` is populated by `import_wp.py` from each WP `<item><guid>` value. Emitted as the RSS `<guid>` element when present, falling back to the canonical URL when absent. **Load-bearing for RSS subscriber continuity at Phase 3.**
- `msm_slug` is populated by `import_msm.py` from the MSM URL the post was recovered from. Used by `sync-msm-redirects.mjs` (see §9.3) to emit per-URL 301 rules when an MSM post is vetted and published, even if the post's new mattiheino.com slug ends up renamed at vetting time.

No other schema changes. `migration_source` already enumerates `'native' | 'mattiheino-wp' | 'motivationselfmanagement'`; `draft`, `vetting_status`, `vetted_on`, `social_status`, `social_copy`, `rigorous_companion`, `applied_companion`, `infographic`, `tags` all stay as designed.

## 6. Phase 2 – WordPress import

### 6.1 Inputs

- `mattiheino-site/migration/source/andoutcomethesystemskyttytymisarkkitehtuuri.WordPress.2026-05-20.xml` (WordPress eXtended RSS export, 2.7 MB).
- `mattiheino-site/migration/source/media-export-95487425-from-0-to-4912.tar` (262 attachments, 113 MB, organised as `YYYY/MM/<filename>`).
- `C:\LocalData\hema\Google Drive\Wordpress` (35 hand-curated image files, flat layout) – used only for dead-external-host image references.

### 6.2 Pipeline (`mattiheino-site/migration/import_wp.py`)

Custom Python pipeline. Builds on the existing `_wp_parse.py` patterns. Stages:

1. **Bootstrap.** Untar the media tar to `migration/source/media/` if not already extracted. Idempotent.
2. **Parse XML.** Use `xml.etree.ElementTree` with the WP namespaces (`wp:`, `dc:`, `content:`, `excerpt:`).
3. **Per `<item>` with `wp:post_type=post`:** see §6.3.
4. **Per `<item>` with `wp:post_type=page`:** see §6.5.
5. **Slug-change diff.** Emit `public/_redirects` entries for any old WP slug differing from the new slug.
6. **Report.** Print a one-screen summary at exit: posts published, posts as drafts, pages imported, pages skipped, images rehosted, images placeholdered, total bytes written.

### 6.3 Per-post pipeline

For each `<item>`:

1. **Frontmatter assembly:**
   ```yaml
   title: <wp:title>
   description: <auto-generated from first paragraph, ≤ 160 chars, sanitised>
   lang: en | fi          # inferred from category → fallback to Unicode heuristic on body
   published: <wp:post_date>           # immutable original publication date
   vetted_on:             # omitted at import time; Matti stamps during vetting
   vetting_status: pending
   migration_source: mattiheino-wp
   draft: false           # wp:status=publish → false; wp:status=draft → true
   tags: [<top WP categories on this post>]  # 8 categories total; see §6.6
   wp_guid: <wp:guid>
   ```
2. **HTML → Markdown:** `<content:encoded>` → `markdownify` (Python lib). Sweep regexes for shortcodes:
   - `[caption ...]…[/caption]` → extract inner `<img>` + caption text; emit standard `![alt](src "caption")`.
   - `[gallery ...]` → leave a `<!-- TODO: gallery #<id> -->` placeholder + log a warning.
   - `<!--more-->`, Gutenberg `<!-- wp:* -->`, `<!-- /wp:* -->` → strip.
   - Inline `<style>` and `<script>` blocks → strip with a warning.
3. **Image pipeline:** see §6.4.
4. **Output:** `src/content/posts/YYYY-MM-DD-<slug>.md` (for `wp:category` containing the post-collection markers) or `src/content/applied-musings/YYYY-MM-DD-<slug>.md` (for the few historical mattiheino.com posts already in a popular register, identified by category).
   - Default collection is `posts/`. The `applied-musings/` placement is a manual override list maintained in `migration/post_collection_overrides.txt` (one slug per line).

### 6.4 Image pipeline

**Destination (single, canonical):**
```
src/content/posts/images/<slug>/<basename>
src/content/applied-musings/images/<slug>/<basename>
```
Served via Astro `<Image>` with `import` statements at the top of each Markdown file's frontmatter sibling layout. Identical pattern to the existing placeholder posts.

**Per `<img src="X">` (and per `<wp:attachment_url>` referenced from the post):**

- **WP-CDN ref** (`mattiheino.files.wordpress.com/wp-content/uploads/<path>` or any host alias that resolves to the same):
  - Strip prefix → relative `<path>`.
  - Look up `migration/source/media/<path>` (untarred cache). On hit, copy to `src/content/<collection>/images/<slug>/<basename>`. Rewrite the Markdown to a relative path. **On miss, log as "expected in tar, absent" and placeholder.**
- **External-host ref** (anything else – `cdn.meme.am`, `daringtodo.com`, `sciencedaily.com`, `pbs.twimg.com`, `helsinki.fi/...`, etc.):
  - Take basename. Normalise: lowercase, strip WP resize suffixes (`-300x200`, `-150x150`, etc.), strip leading `#`.
  - Look up in the GDrive folder index (built once at script start).
  - On hit, copy to `src/content/<collection>/images/<slug>/<basename>` + rewrite.
  - On miss, replace `<img>` with `<!-- IMAGE LOST: src=<original_url> alt="<caption>" -->` in the Markdown body, and append one row to `migration/dead-images-todo.md`.

**`dead-images-todo.md` row format:**
```md
- [ ] posts/2014-11-30-muutoskartta · ¶3
      Original: http://daringtodo.com/.../800px-Montecristo_islet.jpg
      Alt: "Josvain Sitku, zombien kansoittama saari Tyynellämerellä"
      Candidate (GDrive): (none) | (best fuzzy: "luovuus copy.jpg")
```
Browsable independently of vetting. Matti picks a GDrive file (or any file from anywhere), drops it into the appropriate `images/<slug>/`, replaces the placeholder with a proper `<Image>` reference, and ticks the row.

### 6.6 Categories → tags

The 213 long-tail WP tags are dropped. The 8 WP categories become the new `tags:` array. The mapping is hard-coded in the import script (`category-to-tag map`). Reversible by re-running the import.

If a post has multiple categories, all become tags. If a post has zero categories, fall back to the heuristic `["uncategorised"]` and log for manual review.

### 6.7 Slugs and `_redirects`

- Default new slug = WP slug verbatim.
- `cleanSlug()` (existing helper) strips a date prefix if Astro's loader auto-prepends one.
- If the new slug differs from the WP slug (rare), the import script emits an entry to `public/_redirects`:
  ```
  /2014/11/<old-wp-slug>/  /posts/<new-slug>/  301
  /<old-wp-slug>/          /posts/<new-slug>/  301
  ```
  Both the `/YYYY/MM/<slug>/` and bare `/<slug>/` variants are emitted because WordPress.com serves both shapes depending on permalink config.

### 6.8 Drafts

The 17 WP drafts import with `draft: true, vetting_status: pending`. They show on `/vetting-queue/` but not in any public listing. Matti decides per draft whether to finish + publish, or to leave forever.

## 7. Phase 3 – DNS cutover

### 7.1 Pre-flight

- All three RSS feeds (`posts.xml.ts`, `applied-musings.xml.ts`, `all.xml.ts`) emit `<guid>` from `data.wp_guid` if present, falling back to the canonical URL. Add this logic before deploying Phase 3.
- Subscribe to `/all.xml` in Feedly and Inoreader from `new.mattiheino.com`. Verify no items appear (the GUIDs match the WP feed; the readers treat them as already-seen).

### 7.2 Cutover

1. Update Cloudflare DNS for `mattiheino.com` and `www.mattiheino.com` → CF Pages project (was → WordPress.com).
2. CF Page Rule: `www.mattiheino.com/*` → 301 → `mattiheino.com/$1`.
3. Wait for propagation (Cloudflare proxied → seconds).
4. Submit new sitemap to Google Search Console. Leave the WordPress.com sitemap submitted in parallel for ~ 6 weeks until the new URLs are reindexed.
5. Delete the `new.mattiheino.com` custom domain from the CF Pages project. (DNS record removal is a Cloudflare DNS edit.)

### 7.3 Verification gate

- `curl -I https://mattiheino.com/` → 200, served from Cloudflare.
- `curl -I https://www.mattiheino.com/` → 301 to apex.
- `curl https://mattiheino.com/all.xml | xmllint --noout -` → valid XML.
- Spot-check one `<guid>` in the new feed against the same post's `<guid>` in an archived WP feed (or the WP export XML's `<wp:post_meta>`) – they match exactly.
- In Feedly: no new items show in the next 24 hours.

## 8. Phase 4 – MSM Wayback recovery

### 8.1 Inputs

- Wayback CDX list at `%TEMP%\msm_cdx.txt` (re-fetchable via `http://web.archive.org/cdx/search/cdx?url=motivationselfmanagement.com/*&output=text&fl=original,timestamp,statuscode&collapse=urlkey`).
- The 13-post inventory from the plan (12 substantive + 1 unrecoverable).

### 8.2 Pipeline (`mattiheino-site/migration/import_msm.py`)

Per recoverable post:

1. Fetch the best Wayback snapshot (`https://web.archive.org/web/<ts>/https://www.motivationselfmanagement.com/<slug>/`). On 503, retry with a different timestamp.
2. Extract `<article>` body (the `harmonic` theme is reliable). HTML → Markdown via `markdownify`.
3. Frontmatter:
   ```yaml
   title: <recovered>
   description: <recovered or first-paragraph derived>
   lang: en | fi          # per the inventory
   published: <original date>
   vetting_status: pending
   migration_source: motivationselfmanagement
   draft: true           # the gate – stays hidden until Matti flips it
   tags: [...]
   ```
4. Output to `src/content/applied-musings/YYYY-MM-DD-<slug>.md`.

### 8.3 MSM image pipeline

Three sub-procedures:

- **Wayback `im_` infix.** For each `/wp-content/uploads/` ref in CDX (15 hits, all status 200): fetch via `https://web.archive.org/web/<ts>im_/https://www.motivationselfmanagement.com/wp-content/uploads/<path>` with retries. Copy to `src/content/applied-musings/images/<slug>/`.
- **`mattiheino.files.wordpress.com` pre-cutover rescue.** Some MSM posts embed images hosted on Matti's *current* WordPress.com (e.g. `itseohjautuvuus` references `rajoitusmotivaatio.png`). These are alive on the WP-CDN now but will be unreachable after Phase 3. **Must complete this rescue before Phase 3 fires.** Look up each ref in the local media tar (§6.4); on miss, fetch from WP-CDN.
- **Inline images never crawled** (e.g. `antihauras`'s `image.png`, `image-1.png`): leave as `[Image lost in migration]` placeholder; add to `migration/dead-images-todo.md` (separate section: "MSM").

### 8.4 Two special cases

- **`aloittaminen` (no individual Wayback snapshot):** skip the per-post fetch. Add a one-line note to `migration/aloittaminen-decision.md` describing the situation; Matti decides whether to reconstruct from the blog-index excerpt or drop entirely.
- **`personal-change` (Helsinki University origin):** check `helsinki.fi` for the source page first; if found, use that as the source instead of Wayback. If not found, fall back to Wayback.

## 9. Phase 5 – MSM redirects (fallback-only initially)

### 9.1 Setup

Add `motivationselfmanagement.com` as a second custom domain on the CF Pages project. Cloudflare DNS for the apex + www → CF Pages.

### 9.2 Initial `_redirects`

```
https://motivationselfmanagement.com/*       https://mattiheino.com/applied-musings/  301
https://www.motivationselfmanagement.com/*   https://mattiheino.com/applied-musings/  301
```

Every MSM URL lands on the Applied musings index. Acceptable while MSM posts are all drafts.

### 9.3 Per-URL rules as posts go live

When Matti vets and publishes an MSM post (sets `draft: false`), he runs `npm run sync:msm-redirects`. The helper (`scripts/sync-msm-redirects.mjs`):

1. Walks `src/content/applied-musings/`.
2. Selects entries with `migration_source: motivationselfmanagement` AND `draft: false`.
3. For each, reads the `msm_slug` frontmatter field (set by `import_msm.py`).
4. Rebuilds the per-URL rules block in `public/_redirects` (between two sentinel comments, so the script can find and replace its own region without touching mattiheino-WP redirect rules elsewhere).
5. Per-URL rules are placed *above* the catch-all so they take precedence.

Example after one post goes live:
```
# === BEGIN MSM PER-URL (auto-generated) ===
https://motivationselfmanagement.com/safe-changes/      https://mattiheino.com/applied-musings/safe-changes/  301
https://www.motivationselfmanagement.com/safe-changes/  https://mattiheino.com/applied-musings/safe-changes/  301
# === END MSM PER-URL ===

# Catch-all (always last)
https://motivationselfmanagement.com/*       https://mattiheino.com/applied-musings/  301
https://www.motivationselfmanagement.com/*   https://mattiheino.com/applied-musings/  301
```

### 9.4 Verification gate

- `curl -I https://motivationselfmanagement.com/some-random-path/` → 301 → `https://mattiheino.com/applied-musings/`.
- After vetting one MSM post: `curl -I https://motivationselfmanagement.com/<that-slug>/` → 301 → its new home.

## 10. Vetting and marketing pipeline

The schema already supports this; new work is small.

### 10.1 Flow A – mattiheino legacy re-vet

1. Open `/vetting-queue/` (filtered to `posts/` + `applied-musings/` with `migration_source: mattiheino-wp` AND `vetting_status: pending`).
2. Read the post. If it still stands, set:
   - `vetted_on: <today>`
   - `vetting_status: done`
   - `social_status: queued`
3. Optionally tailor `social_copy.<network>` strings per the post.
4. Commit and push. CF Pages rebuilds; the Phase 6 cross-poster (future) picks up `queued`.

Visibility does not change – the post was already live.

### 10.2 Flow B – MSM first publication

1. Open `/vetting-queue/` (filtered to `applied-musings/` with `migration_source: motivationselfmanagement` AND `vetting_status: pending` AND `draft: true`).
2. Read the post. If you want to publish, set:
   - `draft: false`
   - `vetted_on: <today>`
   - `vetting_status: done`
   - `social_status: queued`
3. Run `npm run sync:msm-redirects`.
4. Commit and push. The post is now live; the redirect rule for its MSM URL is in place; the cross-poster picks up `queued`.

### 10.3 `/vetting-queue/` UI

`src/pages/vetting-queue.astro` is updated to split into three sections:

- **mattiheino-wp – pending re-vet** (posts + applied-musings, `migration_source: mattiheino-wp`, `vetting_status: pending`)
- **mattiheino-wp drafts** (`draft: true, migration_source: mattiheino-wp`) – includes the imported WP drafts and the three imported pages (#4, #5, #6 from §6.5)
- **MSM drafts** (`migration_source: motivationselfmanagement`, `draft: true`)

`<meta name="robots" content="noindex,nofollow">` on the page; excluded from sitemap; not linked from public nav.

## 13. Open risks

- **WP-CDN tar coverage.** Assumed comprehensive (262 entries, matches WP export attachment count). If a post references a `mattiheino.files.wordpress.com` URL that is *not* in the tar (e.g. an image inserted post-export), it will placeholder. The dead-images worksheet will catch this.
- **Gutenberg + shortcode residue.** The sweep regexes cover the common cases (`[caption]`, `[gallery]`, `<!-- wp:* -->`). Rare shortcodes will pass through as raw text and look ugly. Manual fix during vetting.
- **Bilingual category inference.** The script infers `lang: en | fi` from category membership. Edge cases (a Finnish post in an English-named category) fall back to a Unicode heuristic. May misclassify 1–3 posts; fixable in vetting.
- **RSS GUID continuity.** If `wp_guid` is wrong for any post (or if the WP export has a malformed `<guid>`), that post re-broadcasts to subscribers. Mitigation: §7.1 pre-flight verifies one GUID by hand; do a second spot-check at random.
- **Wayback flakiness.** Phase 4 fetches may 503 intermittently. The script retries with alternate timestamps; if a specific post never fetches, log and skip (Matti can re-run later).
- **DNS propagation interactions.** Phase 3's `mattiheino.com` cutover and Phase 5's `motivationselfmanagement.com` activation are independent CF DNS operations. Do them in separate sessions to keep blast radius small.
- **Repo size.** Committing the WP-CDN-rescued images into `src/content/<collection>/images/` adds ~ 113 MB of binaries to the repo. Acceptable for a personal site on CF Pages (no LFS needed); future Astro `<Image>` derivatives multiply that during builds (CF caches them).
